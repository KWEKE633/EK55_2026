## 解説
本稿では、NP困難問題に対するグラフ理論からのアプローチ（数理的モデリング）と、Intel AVX-512を用いたハードウェア限界の引き出し（低レイヤー最適化）、そして今後の展望としての極限定数倍最適化の技法について、理論と実装の境界を縫うように解説します。

限界突破の3秒間：多次元制約付き最大重みクリーク探索における数理的枝刈りとAVX-512の極限融合

Author: EK55

Rank: 3rd Place / Fixstars High-Speed Competition 2026

**1. 概要 (Abstract)**

本課題は、N=64 の頂点集合から、128次元のパラメータ制約を満たしつつ重み総和を最大化する完全部分グラフ（クリーク）を3秒以内に発見する制約最適化問題である。状態空間は 2^64に達し、ナイーブな探索では到底計算が追いつかない。  
本解法は、問題を「補グラフにおける最小重み頂点被覆問題」へ等価変換し、グラフの独立辺（マッチング）を利用した強力な下限推定（Lower Bound）を考案した。さらに、その数理的な枝刈り判定をAVX-512命令によってハードウェアレベルの短絡評価へと落とし込むことで、計算量を劇的に削減した。本ドキュメントでは、その思考過程と実装の詳細、およびトップ層の戦いから得られた「さらなる最適化の地平」について論じる。  

**2. グラフ理論による数理的モデリング**

2.1 最大クリークから最小重み頂点被覆への転換
「誰をパーティに入れるか」を加算的に探索するアプローチは、上限（Upper Bound）の見積もりが難しく、探索の枝刈りが遅れるという致命的な弱点を持つ。
そこで、与えられた友人関係の補グラフ（非友人関係のグラフ）を構築し、「誰をパーティから除外するか」を問う最小重み頂点被覆問題（MWVC）へ問題を反転させた。

単調増加性による早期打ち切り: 除外対象（被覆頂点）を追加するたび、失われるスコア（除外コスト）は必ず単調増加する。このコストが「現在発見している暫定ベスト」を超えた瞬間、その先の探索を即座に破棄できる。

2.2 独立辺（マッチング）を用いた多次元下限推定
本解法の最大のブレイクスルーは、鳩ノ巣原理を応用した下限推定の導入である。
補グラフにおいて、端点を全く共有しない「独立した辺の集合（マッチング M）」を抽出する。補グラフにおける辺は「絶対に同時に選べない2人」を意味するため、各辺 e=(u,v)∈M について、少なくとも一方は確実に除外される。
これにより、未来に発生する「不可避な除外コスト」の下限値が以下のように求まる。

Lower Bound= $$\text{Lower Bound} = \sum_{(u, v) \in M} \min(w_u, w_v)$$

この性質は、補グラフがどれほど複雑に連結していようと100%成立する強固な防衛線である。
本実装ではこれをさらに128次元のパラメータ空間へ拡張した。マッチングしたペアについて「各次元パラメータの最小値」を積算し、重みだけでなく「128次元のいずれかが確実にBOSS要求値を割る未来」を数手先で予知し、探索木を根元から刈り取った。

**3. 計算機アーキテクチャと低レイヤー最適化**

アルゴリズムの理論的計算量を落とした後は、C++とCPUアーキテクチャの仕様を突いた泥臭い定数倍最適化が勝負を決める。

3.1 AVX-512による次元圧縮とハードウェア短絡評価
128次元の加算と制約チェックを for ループで回すことは、分岐予測ミスとオーバヘッドの温床となる。そこで immintrin.h を用い、128個の32bit整数を「16要素 × 8本の512bitレジスタ」へパッキングした。

さらに、全次元を計算してから判定するのではなく、マクロ展開による階層的短絡評価（BRANCH_SINGLE）を実装した。
最初の32次元（レジスタ2本）を計算した直後に _mm512_cmpgt_epi32_mask で制約違反のビットマスクを生成。もし1次元でも違反があれば、残りの96次元の命令発行をスキップし、即座にバックトラック（return）を行う。これによりCPUの演算スループットを極限まで節約した。

3.2 メモリアライメントとビット並列操作
キャッシュラインの支配: グラフの隣接行列表現やパラメータ配列はすべて alignas(64) で修飾。AVX-512のアラインド・ロード命令（_mm512_load_si512）がL1キャッシュ境界を跨ぐペナルティを完全に排除した。

ビット並列探索: N=64 の状態管理を uint64_t に押し込め、__builtin_ctzll による最下位ビット抽出や論理積（AND）によって、頂点のペアリングや独立集合の計算を数クロックで完結させた。

3.3 クリーンアップの放棄
コンテストの制限時間は3.000秒。通常の return 0; を行うと、標準I/Oバッファのフラッシュや巨大なオブジェクトのデストラクタが走り、数ミリ秒のロスタイムが生じる。解答を出力した直後に std::_Exit(0)（内部的な syscall）を呼び出し、メモリの解放をOSへ丸投げしてプロセスを即死させることで、計測時間を限界まで削り取った。

**4. 終わりのなき最適化への道（Next Horizons）**

本コンテストの上位陣（1位、2位）のコードや、HPCの知見から得られた「さらに先へ行くための技術的アプローチ」をここに記す。これらは次回以降の戦いにおける重要な武器となる。

4.1 制約の「厳しさ（Tightness）」に基づくデータ再配置
AVX-512による短絡評価の効率（枝刈りヒット率）は、「どの次元から判定するか」に依存する。
上位層は、前処理の段階で128次元のパラメータを「BOSSの要求値に対する余裕がない（違反しやすい）順」にソートしてメモリ上に再配置していた。これにより、最初の32次元のチェックで不合格になる確率が物理的に最大化され、枝刈りの効率が理論値の限界に達する。

4.2 非再帰DFS（状態機械）とカスタムソート
関数呼び出しの排除: std::function や再帰呼び出しは、スタックフレームの構築と破棄にコストがかかる。これを配列ベースの手動スタックと goto を用いた有限状態機械（FSM: Finite State Machine）に書き換えることで、命令キャッシュの局所性を高め、コンパイラの分岐予測をより強力に効かせることが可能になる。

標準ライブラリの剥離: 探索中に行われる微小な配列のソートにおいて std::sort を呼ぶオーバーヘッドすら嫌い、条件分岐をハードコードしたソーティングネットワーク（Sorting Network）を自作することでクロックを削る。

4.3 入力サイズによるアルゴリズムの動的分岐（分岐戦略）
N=64 と N=24 では、最適なアルゴリズムが根本的に異なる。
サイズが小さい場合、強力だが重い下限推定（マッチング計算）を行うよりも、Bron-Kerbosch法で「すべての極大クリークを高速に列挙」し、後からAVX-512で一気に制約判定を通す方が速いケースがある。実行時に入力サイズ N を判定し、L1キャッシュに収まるかどうかの境界で処理系自体を切り替える設計が、トータルスコアの底上げに直結する。

4.4 メモリプリフェッチとキャッシュ・ウォーミング
CPUが計算を行っている間に、次のイテレーションで必要になる頂点のパラメータ配列を _mm_prefetch 命令で非同期にL1キャッシュへ引き上げておく（Prefetching）。メモリレイテンシ（フェッチ待ちのストール）を演算の裏側に隠蔽し、計算機のアイドル時間をゼロにする。

**5. 結論**

本問題は、抽象的なグラフ理論の知識だけでも、C++の低レイヤー技術だけでも解くことはできない。
「数学的なモデリング（補グラフと下限推定）」によって探索空間という名の宇宙を手のひらサイズに圧縮し、「計算機アーキテクチャ（SIMD・メモリ階層）」の物理的挙動を支配してその空間を光の速さで駆け抜ける。
この2つの視点が完全に融合した時にのみ、ソフトウェアは限界を超えた速度を叩き出す。本実装はその一つの証明である。
